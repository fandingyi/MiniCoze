# 第五天：工具与知识网关

日期：2026-10-16。

## 本次完成的闭环

持久化草稿调试通过 Go 读取绑定并冻结能力清单；Python 向模型提供函数定义，接收流式工具参数，再回调 Go。Go 检查权限并执行只读能力，将结果记录到数据库后返回。Python 将结果作为 tool 消息继续交给模型，最终回复仍由第四天事务统一保存。

已实现的能力：

| 能力 | 实现与边界 |
| --- | --- |
| `system_tools__time_now` | Go 内置 UTC 时间查询，无网络请求 |
| `system_tools__echo_text` | Go 内置文本回显，仅接受 text 参数 |
| `knowledge__<稳定摘要>` | 按绑定知识库执行不区分大小写的字面关键词子串检索，返回最多 5 个分块 |

知识检索只读取同工作区、已启用知识库、已绑定知识库、READY 文档和已启用分块。输出含知识库 ID、文档 ID、文档名称、分块 ID、位置与内容摘要。百分号和下划线没有通配符含义。当前没有向量相似度、混合检索、相关性评分或自动引用标记，不应将本实现描述为完整 RAG 检索迁移。

## 权限、预算与记录

- 能力从数据库绑定生成，不信任浏览器传入的工具定义。快照保存资源 ID，模型只看到函数名称、描述和参数结构。
- 新工具执行检查 Run 处于 RUNNING、未过期、用户仍启用且仍属于工作区；同时检查工具/插件/绑定状态、autoInvoke、disabledTools 和知识库绑定。运行开始后新增绑定不会自动进入既有快照；已禁用能力不能发起新的执行。
- 插件仅支持已审查的 BUILTIN system_tools 两个处理器。启用的其他工具能力会被拒绝，不发送任意 URL，也不迁移插件凭据。
- 每个 Run 最多 8 次工具执行（包括保存的失败结果）；Python 最多 5 轮模型请求，最后一轮不能继续调用工具。模型 max_tokens 是每轮限制，不是整个 Run 的累计 token 上限。
- Go 单次工具事务最多 5 秒，Python 网关请求最多 6 秒，整个模型与工具循环共享 Run 的剩余执行预算。知识内容每条最多 2000 字符，模型文本累计最多 1 MiB，网关响应最多 128 KiB。
- 新增 AgentToolCall，以 `(runId, callId)` 唯一标识调用，记录请求指纹、参数、结果、状态和错误码。Run 行锁同时保护调用预算、完成/取消和工具执行。
- 相同 callId、相同请求返回已保存结果，不重新执行；不同请求返回冲突。原结果重取不会重新执行当前绑定检查，但仍要求 Run 活跃、账户与成员资格有效。终态后通过受用户鉴权的查询接口查看记录。
- 参数不合法、未绑定或执行前被禁用的工具返回脱敏失败结果，模型可以在剩余预算内调整；网关不可用、响应不合法或超预算会结束运行，不自动重试。
- SSE 增加校验后的 `tool.call.created` 与 `tool.call.completed`，沿用前端已有字段。终态重建流不重放工具过程；历史工具记录可单独查询。

## 接口与配置

- `POST /internal/v1/runs/{runId}/tools`：Python 专用，使用 RUNTIME_SERVICE_TOKEN；用户 JWT 不能调用。只接受 call_id、name、arguments，身份与资源均从 Run 查询。
- `GET /api/agent-runs/{runId}/tool-calls`：用户 JWT 鉴权，只允许 Run 所有者且仍有工作区资格查看。
- Python 新增 `GO_TOOL_GATEWAY_URL`，例如 `http://127.0.0.1:3001`。这是固定受信任的 Go origin，不从模型或请求参数读取，不跟随重定向。
- 继续使用 `GO_PERSISTED_RUNS=true` 和 `PYTHON_RUNTIME_URL`。开发前端设置 `VITE_GO_API_PROXY_TARGET` 后，工具记录查询也会代理到 Go。

新增 Prisma 迁移：`20261016090000_add_agent_tool_calls`。按现有流程先部署第四、第五天迁移，再生成 Prisma Client，配置并启动两项服务。Go 启动检查 AgentToolCall 表，缺少迁移时明确失败。Python 不会自动读取 .env 文件，需通过环境变量配置。

部署时内部工具路由应仅对 Runtime 的内网服务开放；生产反向代理不能将整个 `/internal/` 转发给浏览器。模型密钥仅发送给固定模型地址，服务密钥仅用于服务间调用。

## 使用步骤

1. 在原管理界面准备已启用的 system_tools 插件，为 Agent 绑定并开启自动调用，启用 echo_text 或 time_now。
2. 为同一 Agent 绑定已启用知识库，确认至少一份文档处于 READY，且相关分块已启用。
3. 保存绑定后，通过配置页的草稿调试发送请求（`preview: true`）。让模型调用工具或检索知识库中的明确关键词。
4. 观察工具创建、完成及最终回复事件，再通过 Run 查询与 tool-calls 接口核对助手消息和引用记录。
5. 禁用工具或知识库绑定后，再发起调用验证拒绝行为。

本次工具支持限于持久化草稿入口。第三天独立无持久化预览仍不支持工具；正式发布运行仍拒绝带能力绑定的 Agent，发布快照能力迁移留到第七天。工作流、HTTP 插件、联网搜索和带副作用工具没有迁移，也没有自动回退或偷偷忽略这些能力。

默认开关仍关闭，没有迁移业务数据库、修改实际密钥配置或切换运行中的服务。
